# Product-owned slave-to-slave copy plans

## Goal

Make the existing quality-carrying `SlaveCopyPlan` a generated product
capability instead of a manually assembled core primitive. A product manifest
must be able to name a source TxPDO, target RxPDO, target quality RxPDO, and
fallback byte; generated artifacts and runtime activation must preserve and
revalidate that exact intent before exposing an immutable plan set.

## Requirements

- Extend the strict `esop.product.v1` manifest with an optional ordered
  `slave_copies` list. Every PDO reference uses slave name plus object index and
  subindex, not generated byte offsets.
- Resolve every reference against the selected ESI PDO set. Reject unknown,
  ambiguous, wrong-direction, same-slave, width/alignment, datagram-coverage,
  and overlapping-target configurations before publishing artifacts.
- Include normalized copy declarations and resolved PDO indices in the
  configuration hash, generated JSON, generated C, and generated Rust.
- Emit a fixed-capacity `no_std` runtime representation. Product activation
  must rebuild all plans from the activated `DomainRegistry` and publish none
  if any plan or capacity check fails.
- Expose the immutable activated plan set so the cycle owner can execute each
  plan after source receive completion and before the target Domain's due TX.
  Existing `SlaveCopyPlan` freshness, WKC, fallback, quality-byte, and atomic
  failure behavior remains the single runtime implementation.
- Replace the current `copy_bytes_per_cycle` approximation with the maximum
  configured slave-copy payload due in any schedule tick.
- Add one checked-in simulator product copy that does not alias CiA 402 command
  fields: left-drive actual position to an IO output mirror plus quality byte.
- Preserve products with no `slave_copies` and keep the cyclic path allocation
  free.
- Document that generated/simulated evidence is not physical HIL, timing
  qualification, or a functional-safety channel.

## Acceptance Criteria

- [x] The checked-in example regenerates deterministically and all six
      artifacts contain the same copy-plan identity and new configuration hash.
- [x] Invalid source/target/quality references and target overlap fail before
      artifact publication.
- [x] Runtime activation exposes exactly the generated plan count and rejects
      tampered indices or insufficient fixed capacity without partial output.
- [x] A public runtime test applies the generated cross-Domain plan, verifies
      copied bytes plus quality in the target frame, and verifies fallback for
      invalid and stale source evidence.
- [x] Legacy empty-copy product tests remain valid.
- [x] `make ci` passes.

## Notes

The existing stable production APIs bind immutable TX images for the duration
of a running cycle. This task exposes product-owned immutable copy plans and
proves their receive-to-target-frame behavior without introducing unsafe image
aliasing. A later task may add a double-buffered or explicitly published
process-image owner for automatic integration with those long-lived bindings.
